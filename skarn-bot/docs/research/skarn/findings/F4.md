# F4 — The "Realm of Skarn": the persistent AI-driven RPG subsystem

Source tree: `skarn-bot/features/realm/` (12 files) + thin wrapper `skarn-bot/commands/realm.js` + realm tables in `skarn-bot/db/skarn-schema.sql` + roles in `skarn-bot/persona/roles.js` + design spec `skarn-bot/docs/specs/2026-07-18/deepseek-v4-flash/realm-of-skarn-final.md`.

## Overview

Realm of Skarn is a fully persistent, single-player-but-shared-world RPG living inside Discord. It is the bot's flagship "AI-first worldbuilding" feature: GPT drives all prose (backstory, exploration narration, NPC dialogue, combat narration, quest hooks), while Node code owns every numeric rule (stats, damage, loot, XP, trade). It is a vertical-slice feature — `commands/realm.js` is a 45-line wrapper (`commands/realm.js:1-44`) whose `execute()` just delegates to `features/realm/realmCommand.js` (`commands/realm.js:42-43`). There are **10 reports + 11 slash subcommands** (create, start/explore, stats, inventory, quests, rest, trade, delete, leaderboard, help) routed by a switch in `realmCommand.js` (`realmCommand.js:868-896`). All game state persists in 7 guild-scoped SQLite tables (`skarn-schema.sql:12-113`), keyed by `(user_id, guild_id)`.

## Game flow (end-to-end)

**1. Creation — 5-step wizard** (`realmCommand.js:64-201`): `/realm create` walks the player through step 1 name (free text via `awaitMessages`), step 2 race (buttons), step 3 class (buttons), step 4 background free-text, step 5 AI backstory with Accept/Reroll. Guards: existing character blocks re-create (`realmCommand.js:68-75`), name 2–32 chars (`realmCommand.js:90-92`), 60s timeout per step. Backstory is AI-generated via `generateBackstory()` (`realmCommand.js:164`, `aiDriver.js:51-54`), and a reroll falls back to a static default line (no re-call) (`realmCommand.js:182-190`). Character stats are derived purely from race+class combos (`realmConfig.js:3-45`), with luck random 1–10 (`character.js:25`), HP = `20 + con*5 + level*3` (`realmConfig.js:212-214`).

**2. Explore — the core loop** (`realmCommand.js:205-417`): `/realm start`/`/realm explore` calls AI `generateExploration()` (`realmCommand.js:239`, `aiDriver.js:56-59`), parses the AI's numbered lines `1. text` into choices via `parseChoices()` (`world.js:40-56`), renders 1–4 buttons (`realmCommand.js:30-37`, `realmCommand.js:658` spec allows variable counts). A 120s message-component collector handles each click (re-enter combat if already fighting, `realmCommand.js:214-219`). Choice parsing at `realmCommand.js:291-417`:
- **Move to a connected location** if the choice text mentions a neighbor (`realmCommand.js:308-311`, `320-346`) → validated against the connection graph by `moveTo()` (`world.js:22-36`) → persists location + discovery + quest-progress check (`realmCommand.js:324`).
- **NPC interaction** if the choice names a pooled NPC (`realmCommand.js:313-315`, `347-384`).
- **Combat trigger** if the choice has combat keywords OR a random roll `0.12 × dangerLevel` (`realmCommand.js:317-318`, `385`).
- Otherwise a free narrative scene (`realmCommand.js:395-416`).
A per-user cooldown `realm:<guild>:<user>` (30s, SQLite `cooldowns`) is the double-submit/re-entrancy guard (`realmCommand.js:221-223`, `259-263`).

**3. Fight — turn-based, code-calculated damage, AI-only narration** (`combat.js:1-341`): `rollEnemy()` scales the enemy from `ENEMY_SCALING` by danger level (`combat.js:23-44`, `realmConfig.js:186-195`). `startCombat()` opens an in-memory session with a 5-minute timeout (`combat.js:48-81`). `processCombatRound()` computes player damage = `math.max(1, (primaryStat + weaponBonus) × critMult − enemy.defense)`, crit chance = `luck/100` (`combat.js:135-153`), enemy damage = `max(1, enemy.attack − playerDefense × defensemult)` (`combat.js:156-161`). **Player HP is persisted to SQLite after every exchange** (`combat.js:176`; spec §S7d) so a mid-fight restart never resets HP. Outcomes: victory → XP+gold+`generateLoot()`+`equipBest()` (`realmCommand.js:443-478`); defeat → lose 50% gold, HP set to 1 (`combat.js:224-234`); timeout → lose 10% gold (deliberately smaller than the 50% defeat penalty, spec §S7e) (`combat.js:288-292`).

**4. Quest — AI hook, code-tracked objectives** (`quest.js:1-139`): quest-giver NPCs trigger `generateQuestHook()`; the AI's `Title:/Description:/Reward:` lines are regex-parsed into objectives by code (`realmCommand.js:353-373`). Max 3 active quests (`quest.js:4`). `checkQuestProgress()` auto-increments objective `current` on matching explore/kill events and completes the quest (`quest.js:46-97`).

**5. Trade — player-to-player** (`economy.js:1-318`): `/realm trade @player` (`realmCommand.js:666-779`) with self-trade guard and one-active-trade-per-user (`economy.js:11-26`). Both players add items/gold via a select menu ("Add item" → paginated up to 25 options) and confirm in a 5-minute window (`realmCommand.js:682-757`). Completion runs inside a **single SQLite transaction** (`economy.js:176-196`) with fail-closed inventory verification (`economy.js:155-174`). Non-player trade: `sellToMerchant()` applies a friendly-relationship 1.1× multiplier and refuses hostile players (`economy.js:230-256`).

**6. Rest / stats / inventory / leaderboard**: `/realm rest` heals 25% (`character.js:162-176`), `/realm stats` shows the sheet (`realmCommand.js:520-546`), inventory paginates 25/page (`inventory.js:146-160`), leaderboard is guild-scoped top-10 by level (`realmCommand.js:823-840`).

## Design decisions

- **Damage by code, narration by AI** (the central invariant): every formula lives in `combat.js`; the AI only receives already-computed numbers and describes them (`src spec §S7b1` "The AI narrates but does NOT decide outcomes", and the combat role line enforces it, `roles.js:33`). Temperatures are higher for narration (0.8–0.9) precisely because none of it drives outcomes (`aiDriver.js:22,53,58,63,69,74`).
- **Separate AI driver with its own context builder**: `aiDriver.js` has `buildRealmContext()` (`aiDriver.js:7-19`) — it builds a compact character/location/NPC/quests/NPC-memory context string and calls `callAi()` (`aiDriver.js:21-49`) which uses `buildSystemPrompt()` + the `roles.realm`/`realm_combat`/`realm_npc` role lines and a 30-second abort timeout (`aiDriver.js:28-29`). It passes an explicit `bucket: 'realm'` to `moderatedChatCompletion()` (`aiDriver.js:34`).
  - **Drift note (code vs CONTEXT.md/spec):** the spec (§S12) and CONTEXT.md claim the realm driver "hardcodes `model: 'gpt-5.4-mini'` and ignores the model router." The **actual code does not** — `aiDriver.js:3` imports `selectModel` and line 26 calls `selectModel(message)`, so it routes through the shared `modelRouter.js` (which resolves `AI_MODEL`/`AI_MODEL_COMPLEX`, default `gpt-3.5-turbo`; `modelRouter.js:4-13`). The documented "hardcoded model / isolates from model router" behavior is not what the current tree implements.
- **Separate rate limiting**: `realmRateLimit.js` is a distinct bucket from the bot-wide limiter. Per-user: 30 calls per rolling 30-min window stored in `app_flags` under `realm_bucket:<userId>` (`realmConfig.js:199-202`, `realmRateLimit.js:7-26`). Per-guild: daily counter in `realm_world_state` under `daily_ai_calls`, capped by `REALM_DAILY_CALL_LIMIT` env default 1000, reset at UTC midnight (`realmRateLimit.js:30-51`, `realmConfig.js:204`). All roll calls are `canCall()` + `canGuildCall()` gated before each AI call (`realmCommand.js:156,231,326`, `combat.js:238`, etc.). Rationale in spec §S12f: reusing the global bucket would let one session exhaust the whole bot budget.
- **In-memory combat & trade sessions with 5-minute timeouts**: `activeCombats` Map (`combat.js:9`) and `activeTrades` Map (`economy.js:5`) are intentionally volatile game-session state (lost on restart, per CONTEXT §2); the 5-min timeout is set in `startCombat` (`combat.js:70`) and via the trade collector + `TRADE_TIMEOUT` (`economy.js:7`, `realmCommand.js:696,772-778`). Persistent state (char, inventory, quests, NPC memory, kills, discoveries) lives only in SQLite.
- **Atomic SQLite trades**: `executeTrade()` (i) re-verifies both offers against fresh inventory reads and fails closed before mutating (`economy.js:154-174`), then (ii) runs all item/gold transfers inside `db.transaction(() => {...})` (`economy.js:176-196`), rolling back on any error (`economy.js:198-203`).
- **NPC memory & relationship**: per-NPC memory in `realm_npc_memory` (last 5 interactions), relationship = running average of sentiment (friendly ≥ +2, hostile ≤ −2) (`realmStore.js:144-151`); hostility flips merchant trade refusal (`economy.js:234-237`) and can turn a neutral NPC into an enemy (`npc.js:54-56`).
- **Anticipated-but-not-implemented from spec**: the double-submit "isProcessing" in-memory flag is realized instead as a SQLite cooldown key (`realmCommand.js:221-223`).

## Content-safety restrictions in the role lines

In `persona/roles.js` (these are injected into every realm system prompt — not advisory):
- `realm` (`roles.js:32`): "Keep tone in the register of fantasy adventure fiction — **no gratuitous gore, no romance or dating-style content**."
- `realm_combat` (`roles.js:33`): "**Fantasy violence only — no gratuitous gore.**"
- `realm_npc` (`roles.js:34`): "Never break character or reference being an AI."
These are the load-bearing content guardrails for the subsystem (documented in CONTEXT §7.1). Additionally `combat.js:246-248` filters AI narration that drifts into Warmaster/meta/"can't/unable/error" text before display.

## Distinctive choices

1. **The AI is a narrator, never an adjudicator.** Every number (damage, crit, loot, XP, quest completion, trade execution) is decided by deterministic Node code; the LLM writes prose and offers numbered choices that code maps to mechanics. This inverts many LLM-RPG designs and keeps combat/trade exploit-proof and deterministic (CONTEXT §3, spec §S7b1).
2. **A self-contained AI driver with its own context builder and bucket**, passing `bucket:'realm'` so the subsystem is siloed from bot-wide throttles — and (per spec/CONTEXT docs) intended to hardcode a model and ignore the router, though the current code actually delegates to `selectModel()` (drift noted above).
3. **Dual, independent rate-limit walls** (30 calls/30 min per user AND 1,000 calls/day per guild) protecting the AI budget from heavy play; hitting either returns a distinct static in-character line, never a bot call.
4. **Deliberately volatile live-game sessions vs durable world**: combat and trade are in-memory Maps with 5-minute timeouts (safe to lose on restart) while every piece of progression is SQLite-persisted and guild-scoped — including player HP written per combat round to defeat a restart exploit.
5. **Anti-exploit math written into the design**: defeat costs 50% gold but a combat timeout costs only 10% (spec §S7e reasoning: timeout is never a strictly-better option); max-level XP converts to gold at 1:1 rather than being wasted (`character.js:115-118`); trades verify-and-transact atomically in one SQLite transaction, failing closed on any inconsistency.
6. **Guild-scoped shared-but-solo world**: each Discord server is a self-contained realm; a user in two servers has two separate characters, and discovery/leadership/kill-stats never leak across guilds (`world.js`, `realmStore.js`, spec §S11a).
7. **Content is constrained in the role line, not after the fact**: gore/romance bans live directly in the system prompt for every realm call (`roles.js:32-34`), front-loaded rather than post-filtered (only combat narration adds a second regex safety filter, `combat.js:246-248`).
