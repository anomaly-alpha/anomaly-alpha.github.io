## 1. Overview

Skarn is a **Discord.js v14 + Node.js bot** that runs an LLM-powered persona ("Skarn, the
Warmaster of the Abyss"). It is a single-process bot rooted in `bot.js`, loads ~75 slash
commands, and bolts on an extensive set of "vertical slice" feature modules that make the bot
behave like a living character rather than a command dispatcher.

Key architectural signatures:

- **Vertical-slice features.** Each personality subsystem lives in `features/<name>/` as
  `commands/<name>.js` (thin wrapper) + `features/<name>/<name>.handler.js` (logic) +
  `features/<name>/<name>.command.js` (slash definition). `docs/ARCHITECTURE.md:81-92`.
- **Two shared layers cut across every feature** (`CONTEXT.md §2`):
  1. `buildSystemPrompt()` in `persona/identity.js` — the single assembler for every AI
     system prompt (core identity + role line + all context lines).
  2. The **activation registry** (`features/activation/activationRegistry.js`) — a
     deterministic, startup-built map of `"skarn <phrase>"` → command/AI routing.
  3. The **AI tool system** (`features/tools/toolDefinitions.js` + `toolRunner.js`) — OpenAI
     function calling for the shared pipeline.
- **Shared AI pipeline.** `features/ai/sharedPipeline.js#runPipeline()` is the single
  message→AI-reply engine used by BOTH `/consult` and `@Skarn` mention, eliminating ~90%
  duplication that previously existed between `consult.handler.js` and `mentionRouter.js`
  (`CONTEXT.md §12.5`).
- **All state in SQLite.** Cooldowns, rate limits, memory, mood, relationships all persist to
  `data/skarn.db`. No migrations — schema is `CREATE TABLE IF NOT EXISTS` each boot
  (`docs/ARCHITECTURE.md:265`).
- Dependencies: OpenAI (generation + moderation), Tavily (web search), Discord.js. Zero test
  framework ("deliberately test-free", `CONTEXT.md §11.2`).

Two distinct routing philosophies coexist (see §4):
- **Deterministic prefix routing** — the activation registry: exact phrases like
  `skarn weather`. Deterministic, git-visible.
- **Model-decided function calling** — the 10 AI tools offered in the shared pipeline on turn 1.
  Fuzzy, model-decided.

## 2. Message flow: Discord → AI reply → back

### 2.1 Entry: `bot.js` `messageCreate`

All inbound text funnels through a single `messageCreate` handler (`bot.js:170`). It applies
a strict, commented, numbered pipeline of gates:

1. **Skip bots** (`bot.js:172`), and **dedupe** each message ID at most once via a bounded
   `Set` of the last 500 (`bot.js:174-181`). This prevents the same message being processed
   twice by concurrent paths (`CONTEXT.md §9.2`).
2. **Skip `*`/`+` prefix markers** (`bot.js:184`).
3. **DM handling** (`bot.js:189-213`): auto-opts-in the user, checks the activation registry,
   else routes to AI via `safeHandleMention`.
4. **Non-blocking state tracking batch** (`bot.js:215-232`): wrapped in `Promise.allSettled`
   so tracking failures never block the reply. Updates channel state, relationship
   familiarity, server culture, warmth, humor callbacks, banter chains, punchline setups, and
   an AI-channel message counter.
5. **Fast-path skippers** (`bot.js:234-262`): `skarn opt in/out`, `skarn chat mode`,
   `skarn status` return immediately, no AI.
6. **Activation registry** (`bot.js:265-298`): if content starts with `skarn` or `!`, the
   registry `lookup()` runs. `type:'command'` dispatches directly to the handler;
   `type:'ai'` rewrites `message.content` to inject a directive and routes to AI. If the bare
   word `skarn` appears without a phrase match, it also falls through to AI (`bot.js:294-297`).
7. **@mention → AI** (`bot.js:300-304`).
8. **Passive reactions** (`bot.js:306-320`), sleep-aware.
9. **AI-channel auto-respond** (`bot.js:322-350`): only in configured `aiChannels`, skips
   ignored users, follows reply-to-bot, then gates via `attentionGate.shouldRespond()`.
10. **XP + record** (`bot.js:352-362`); **message log** (`bot.js:364-370`);
    **passive interjection** (`bot.js:372-375`).

### 2.2 To the AI: `handleMention` / `execute`

Two entry points hand off to the shared pipeline:

- `features/mentionRouter/mentionRouter.js#handleMention()` (`mentionRouter.js:6`): used for
  `@mention`, DM, AI-channel, and `type:'ai'` activation routes. Checks in-order:
  bot skip → opt-in (`canInteract`) → **hourly cap** (`canRespond`) → strip the `<@id>` →
  **hostile check** → **silenced check** → 10%-reaction-only shortcut →
  `runPipeline(...)` with `chunkSize 1900`, `temperature 0.85`, role `'consult'`.
- `features/consult/consult.handler.js#execute()` (`consult.handler.js:5`): slash-only,
  server-only, deferReply first, then its own silenced/hostile pre-checks → `runPipeline(...)`
  with `chunkSize 400`, `temperature 0.8`, edit-capable (`canEdit:true`).

### 2.3 The core: `runPipeline` (`sharedPipeline.js`)

`runPipeline(userId, guildId, channelId, message, opts)` (`sharedPipeline.js:47`):

1. **Typing keepalive** — a Discord "typing..." indicator stays visible for the ENTIRE thinking
   duration, not just a post-generation pause (`sharedPipeline.js:57`).
2. **Persist the user message** to the conversation store (`sharedPipeline.js:60`).
3. Read relationship/interaction count; detect & store user emotion (async)
   (`sharedPipeline.js:62-66`).
4. **Preprocessing pipeline** (`sharedPipeline.js:75-93`): `preprocessing/pipeline.js` runs
   stages Analyze → Retrieve → Assemble. `analyzeMessage` (with one 100ms retry), then
   `retrieveContext`, then `assemblePrompt`. If it produces a prompt it is used; otherwise it
   falls back to `buildContext()` + `buildSystemPrompt()`.
5. **Banter escalation**, **knowledge match**, **story engine injection** (a recalled tale is
   appended to the user message) (`sharedPipeline.js:95-106`).
6. **Reply char target** appended to the system prompt (`sharedPipeline.js:108-111`).
7. **Tool-enabled, multi-turn loop** (see §4): offers `getTools()` with `tool_choice:'auto'`
   ONLY on turn 1; up to `maxTurns = 3` (`sharedPipeline.js:118-157`). Tool results are
   appended and looped back until the model produces a plain-text reply.
8. **Condense** over-target replies via `condenseReply()` (`sharedPipeline.js:164-170`).
9. Persist assistant reply, track sentiment shift, store any new story, detect follow-ups
   (`sharedPipeline.js:172-191`).
10. **Authenticity pacing** — `simulateTyping()` + `estimateDelay()`; a longer pause if the
    reply is a punchline (`sharedPipeline.js:195-204`).
11. **Usage counter** — if ≥ 40/50 calls used, a `-# (40/50)` suffix is appended so the user
    sees the budget almost exhausted (`sharedPipeline.js:207-208`).
12. **Split and send** — `splitMessage()` in chunks (`chunkSize` varies), with `maybeBurst()`
    for the tail; edit-capable path for consult (`sharedPipeline.js:210-230`).
13. Post-reply hook, then **auto-extract memory** (non-blocking) (`sharedPipeline.js:233-236`).
14. On any error: flag for apology; on crisis: `onCrisis()`; else a themed error string
    (`sharedPipeline.js:237-244`). `stopTyping()` in `finally`.

### 2.4 The gate: `moderatedChatCompletion` (`ai/client.js`)

Every AI call — generation, moderation, and even the condenser — funnels through
`moderatedChatCompletion()` (`ai/client.js:41`), which is the single **admission + safety
gate** (see §5).

## 3. Tiered context assembly (lightweight / full / advice)

**ADR `docs/adr/0001-tiered-context-assembly.md`** defines a 3-tier `buildContext()` to keep
short messages cheap. Implemented in `features/promptContext.js`.

### Trigger rule

`let isFullTier = userContent.length >= 50 || userContent.indexOf('?') !== -1;`
(`promptContext.js:28`). Note `isFullTier` is `let`, not `const` — specifically so the socratic
line can promote a message to full tier.

### Lightweight tier (default; < 50 chars and no `?`)

- All directive lines (state, mood, relationship, culture, warmth, patience, memory,
  emotional, safety, news, examples, lore), plus **last 3 messages only**, no summaries /
  profile / knowledge / buzz / RAG (`promptContext.js:122-131`).
- ~1,000 tokens (`docs/ARCHITECTURE.md:216`).

### Full tier (>= 50 chars or contains `?`)

Everything in the lightweight tier plus, from `promptContext.js:81-121`:
- Last **15** messages (`promptContext.js:84`).
- **2** conversation summaries (`promptContext.js:89-96`).
- **Server buzz** — last 10 user messages in the guild, distilled into top-3 topic fragments
  (`promptContext.js:99-106`).
- **User profile** — top topics + engagement level (`promptContext.js:108-117`).
- **Knowledge base** match via `searchKnowledge()`, formatted
  (`promptContext.js:119-121`).
- **Semantic RAG** — cosine-similarity over recent conversational message embeddings when >= 5
  exist, threshold 0.4, cached into `app_state` for the *next* turn
  (`promptContext.js:154-193`).
- **Server wisdom** — recent `server_signals` (`promptContext.js:214-228`).
- ~3,000 tokens (`docs/ARCHITECTURE.md:217`).

### Advice tier

Per ADR: full tier + a socratic directive (`docs/adr/0001-tiered-context-assembly.md:31-33`).

The current implementation (**live**, via `getSocraticQuestion()`):
```
const socraticLine = getSocraticQuestion(userContent);
if (socraticLine && !isFullTier) { isFullTier = true; }
```
(`promptContext.js:30-33`). So a message that matches an advice trigger is **promoted to full
tier** — the most expensive path — even if it is short and has no `?`. The socratic engine in
`features/wisdom/socraticEngine.js` matches 18 trigger phrasings (e.g. `help me think`,
`i can't decide`, `what would you advise`) (`CONTEXT.md §5`). The returned `socraticLine` is
injected into the system prompt via `buildSystemPrompt()` (`identity.js:155`).

> Note: `docs/ARCHITECTURE.md:218-220` still labels the Advice tier "not implemented / dead
> surface area", but this is **stale** — `CONTEXT.md §5` records it as resolved
> (2026-08-01) and the code clearly populates `socraticLine` (`promptContext.js:30`).
> Documented drift between docs and code.

The news line is **always-on** regardless of tier (`promptContext.js:65-74`): newest article
per category, top 3 overall, `[cat] headline` format — after the NL-command upgrade it is no
longer intent-gated (`CONTEXT.md §6.1`).

Safety line is built by `buildSafetyLine()` and included on every tier (`promptContext.js:134`).

## 4. Tools: model-decided function calling vs deterministic activation registry

Two **deliberately distinct** command systems coexist (`CONTEXT.md §2`).

### 4.1 Deterministic activation registry (`skarn <phrase>`)

`features/activation/activationRegistry.js`:

- Built **at startup** by `scanCommands()` — iterates every file in `commands/`, reads each
  module's `activation` export, and registers the phrase (`activationRegistry.js:25-41`).
- `register()` stores `{command, type, handler, activation}`; `sortedPhrases` is kept sorted
  **longest-first** so the most specific phrase wins on a prefix clash
  (`activationRegistry.js:22`).
- `lookup(content)` (`activationRegistry.js:43-81`): exact, deterministic, lowercase prefix
  match with **word-boundary enforcement** (next char must be whitespace/punct)
  (`activationRegistry.js:70-74`). Also supports `!cmd` as shorthand → `skarn cmd`
  (`activationRegistry.js:48-56`) and strips an optional `<@bot_id>` mention prefix
  (`activationRegistry.js:63-68`).
- Two routing types (`activationRegistry.js:86-107`):
  - `type:'command'` → runs the handler directly with parsed args (`buildMatch`).
  - `type:'ai'` → rewrites content into a directive (`[The user requested "<phrase>".
    Respond accordingly...]`) and routes to the AI pipeline.
- `getAll()` (`activationRegistry.js:109-121`) exposes every registered activation — this is
  what feeds the AI tool enum (§4.2).

### 4.2 Model-decided AI tools (10 tools)

`features/tools/toolDefinitions.js` — JSON-Schema function declarations offered only to the
model, with `tool_choice:'auto'`, on **turn 1** of the shared pipeline
(`sharedPipeline.js:133`).

The 9 fixed `coreTools` (`toolDefinitions.js:14-136`):
1. `etch_memory` (userId, fact) → `addMemoryEntry(...,'etch','fact',1.0)`
2. `get_memory` (userId) → lists etched + extracted memories with confidence
3. `search_web` (query) → Tavily via `searchEngine`
4. `set_reminder` (userId, message, duration) → parse `30m/2h/1d`, clamp 1min–1yr,
   `createReminder`
5. `get_weather` (location) → `fetchWeather` (3-day forecast)
6. `get_news` (category) → cached headlines; on-demand `fetchNews` if empty
7. `roll_dice` (sides 2–100) → `getDiceResponse`
8. `flip_coin` → `getCoinflipResponse`
9. `get_user_stats` → `getStatsData` (message/question/thread/topics/engagement)

Plus the **10th, generated** tool:

10. `run_command` (`toolDefinitions.js:150-168`) — lets the model invoke *any*
    activation-registered command. Its `command` enum is **built dynamically each call** from
    `activationRegistry.getAll()` (filter `type:'command'` minus `EXCLUDED_COMMANDS`
    `['dice','coinflip','stats','weather','news','etch','remind','memory','search','lore']`)
    (`toolDefinitions.js:12, 141-146`). Because it is generated per `getTools()` call, a newly
    activated command automatically appears in the tool (`toolDefinitions.js:148`).

### 4.3 How `run_command` executes

`toolRunner.js#runTool()` `run_command` case (`toolRunner.js:162-245`):

- Normalizes the model's name (strips a leading `skarn `), validates against
  `getRunCommandNames()` (defense-in-depth beyond the schema enum),
  require()s `commands/<name>`, and confirms `activation.type === 'command'`.
- Builds a **pseudo-message facade** via `buildFacade()` in `features/tools/messageAdapter.js`
  (see below) so the **unmodified** `handleActivation` handler runs.
- Applies `guildOnly` + `requiredPermissions` gates fail-closed ("You need X permission...")
  (`toolRunner.js:199-213`).
- Dispatches through `handleActivation(facade, parsedArgs)` — **never**
  `execute(interaction)`, so **no nested AI from a tool** (recursion guard)
  (`toolRunner.js:226-231`; `CONTEXT.md §2`). One approved exception: poll's blank-options
  AI suggestion flow.
- `facade.capture()` returns the text the handler "replied" so the **tool result carries the
  real output** back to the model (`toolRunner.js:234-240`), with an instruction to reply in
  <=1 line.

**`messageAdapter.js` (`buildFacade`)**: wraps the real Discord message (prototype inherited,
content/mentions/reply shadowed) for the mention path (`messageAdapter.js:44-56`), or
synthesizes one from the interaction (`interaction.user/member/guild/channel/client`) for the
consult path (`messageAdapter.js:58-76`). `parseMentions()` regex-parses `<@id>`, `<#id>`,
`<@&id>` (`messageAdapter.js:8-24`).

**Tool loop** (`sharedPipeline.js:124-157`): up to `maxTurns = 3`. On a turn where the model
returns `tool_calls`, the assistant message + each tool result are pushed back into `messages`
and the loop continues until the model emits a plain-text `choice.content`.

### 4.4 Registry vs tools — the key contrast

| | Activation registry | AI tools |
|---|---|---|
| Who decides | User / deterministic prefix | The LLM (`tool_choice:'auto'`) |
| Trigger input | Exact `skarn <phrase>` / `!<cmd>` | Natural language ("what's the weather in Tokyo?") |
| Match semantics | Prefix + word boundary, exact | Fuzzy, model-decided |
| Discovery | Startup scan of `commands/*.js` `activation` export | `getTools()` reads the registry's `getAll()` |
| Nested AI | Commands may call AI | Tools must not call AI (recursion guard) |

(`CONTEXT.md §2`, `activationRegistry.js`, `toolDefinitions.js`.)

## 5. Rate limiting, moderation & silencing — where they are enforced

### 5.1 Rate limiting — per-concern buckets, not one global limiter

`CONTEXT.md §4`: separate buckets per concern, each its own SQLite table:

- **General AI calls** — `rate_limits` via `lib/rateLimit.js`. **Atomic reserve**:
  `canCall()` INSERTs a row and returns its rowid as a reservation
  (`rateLimit.js:24-35`); `releaseCall()` deletes it (cancels the reservation)
  (`rateLimit.js:37-41`). Sliding 10-min window; `RATE_LIMIT_MAX_CALLS = 50`
  (`rateLimit.js:12-13`). This is the admission gate **inside `moderatedChatCompletion()`**
  (`ai/client.js:52-55`).
- **Hourly cap** — `ai_usage` via `lib/aiStats.js` `canRespond()`:
  `HOURLY_CAP = 50`/hour per user (`aiStats.js:3,21-31`). Checked early in
  `mentionRouter.handleMention()` (`mentionRouter.js:18`).
- **@mention cooldown** — `mention_cooldowns` (1s), **interjection** & **active-listening**
  cooldowns (5min), **reaction cooldown** (generic `cooldowns`) — all SQLite-backed since the
  2026-08-01 "all state in SQLite" audit (`CONTEXT.md §4, §12.4`).
- **Realm RPG** — separate bucket: 30 calls/30min/user + 1,000/day/guild, independent
  (`docs/ARCHITECTURE.md:254`).
- **Condenser** — uses its own `'condense'` bucket through the same gate (`condenser.js:44`).

Why separate buckets: prevents one feature's traffic (e.g. reaction spam) from starving AI
replies (`CONTEXT.md §4`). A new AI-calling feature must add a new bucket.

### 5.2 Moderation & silencing — centralized in `moderatedChatCompletion()`

`ai/client.js` is the single chokepoint for all AI calls (`ai/client.js:41`). Per call it:

1. **Silence gate** — `isSilenced(userId)` returns a de-escalation line and skips the call
   entirely (`ai/client.js:49-51`).
2. **Rate-limit reserve** — `canCall()`; if denied, returns the pacing message
   (`ai/client.js:52-55`).
3. **Input moderation** — `moderateInput()` via OpenAI `omni-moderation-latest`. Returns
   `{action:'crisis'}` on self-harm categories, `{action:'block'}` on anything else flagged,
   `{action:'pass'}` otherwise (`ai/client.js:14-39`). **Violence/harassment is explicitly
   allowed through** so Skarn can tell battle stories in-character
   (`ai/client.js:23-32`, `97-112`). Fails closed on moderation error
   (`ai/client.js:35-38`).
4. **Generation** — passes `moderation:{model:'omni-moderation-latest'}` into the OpenAI call
   for output moderation (`ai/client.js:76`); filters unknown gate params (userId/bucket/
   signal not leaked) (`ai/client.js:79-84`).
5. **Output moderation** — reads `completion.moderation.output`; blocks non-self-harm flagged
   content; fails closed when output moderation is unavailable or errors
   (`ai/client.js:87-121`).

### 5.3 Hostile detection / strikes (slurFilter)

`features/safety/slurFilter.js` — a 3-strike + silence system:

- 10 regex patterns match hostile phrases (`you're useless`, `kill yourself`, etc.)
  (`slurFilter.js:11-15`).
- `recordStrike(userId)` bumps a per-user counter in `app_flags` (key `strike_<id>`, 10-min
  TTL); at 3 strikes sets `silencedUntil = now + 10min` (`slurFilter.js:50-63`).
- `isSilenced()` returns true while silenced (`slurFilter.js:65-68`).
- Strikes are **input-only** (flagged AI output no longer records a strike) (`CONTEXT.md §13`).
- Pre-checks run in `mentionRouter.handleMention()` (`mentionRouter.js:25-31`) and
  `consult.handler.js` (`consult.handler.js:13-22`); the actual hard gate is **enforced
  centrally** in `moderatedChatCompletion()` (`ai/client.js:49-51`).
- The original `hostileDetector.js` and a separate `slur_filter` DB gate were deleted in the
  2026-08-01 audit; only prompt-internalization (Gate 1) + OpenAI moderation remain
  (`CONTEXT.md §13`).

### 5.4 Other cost/safety controls

- **Sleep mode** — `isSleepTime()` from `SLEEP_START`/`SLEEP_END` (default 1–7 UTC): blocks
  slash replies (`bot.js:123-125`) and skips mentions/interjections (`bot.js:318`, `374`).
- **Reaction-only mode** — `shouldReactOnly()` 10% chance for casual intents sends only an
  emoji, no AI text (`mentionRouter.js:35-38`; `CONTEXT.md §7.4`).
- **Proactive opt-in** — `proactive_opt_in` defaults to 0; proactive messages require opt-in
  (`mentionRouter.js:10-12`).
- **Deadpan budget** — `getDeadpanBudget()` shrinks `max_tokens` during banter chains
  (`sharedPipeline.js:129`).

## 6. Most distinctive engineering choices

1. **Two gate routing systems that see nothing like each other.** Deterministic activation
   registry (`skarn <phrase>`, startup-scanned, word-boundary exact) coexists with
   model-decided OpenAI function calling (10 fuzzy tools). They are *combined*, not either/or,
   and the AI `run_command` tool is **generated live from the deterministic registry** —
   `toolDefinitions.js:141-146` reads `activationRegistry.getAll()`. A new `skarn <cmd>` phrase
   automatically becomes an AI-callable tool.

2. **The pseudo-message facade (`messageAdapter.js`).** To let the model "run any command",
   the bot fabricates a Discord Message object (or re-wraps the real one) exposing
   `author/guild/member/mentions/reply()`, runs the unmodified `handleActivation` handler, and
   **captures its reply text** so the tool result carries the real output back to the model.
   Execution is enforced through `handleActivation`, never `execute(interaction)`, to prevent
   recursive nested AI (`messageAdapter.js:44-76`, `toolRunner.js:226-231`).

3. **Tiered context that is *counter-intuitively* most expensive for advice.** Short advice
   messages ("help me think...") are **promoted to full tier** purely because a socratic question
   matched (`promptContext.js:30-33`), burning ~3,000 tokens on the shortest messages. The
   doc (`docs/ARCHITECTURE.md:218-220`) still claims this tier is unimplemented.

4. **Every AI call — including moderation and the reply condenser — funnels through a single
   atomic gate.** `moderatedChatCompletion()` unifies rate-limit reservation, silence check,
   input moderation, generation, and output moderation in one place (`ai/client.js:41-129`).
   Rate limit is a *reservation* (INSERT rowid) that is released on any failure to avoid
   burning user quota (`rateLimit.js:24-41`).

5. **Authenticity is code, not a prompt.** Typing keepalive across the entire thinking time,
   simulated typing delay, estimated human delay, punchline pauses, message splitting/bursting
   into chunks, probabilistic post-processing (lowercase, abbreviations, emoji) — all applied
   *after* the AI reply is generated (`sharedPipeline.js:195-230`,
   `features/discordNative/`). The bot is engineered to feel human-paced.

6. **A reply condenser is a second LLM pass with fail-open discipline.** `condenseReply()`
   only fires when the draft exceeds the char target, **explicitly short-circuits with zero LLM
   call when already within target**, skips structured content (code fences/tables) and tool-call
   replies, rejects output shorter than 16% of target, and fails open to the original on any
   error (`condenser.js:22-71`). It uses a distinct `'condense'` rate-limit bucket and a cheaper
   model (`gpt-4.1-mini`).

7. **Explicit "let it be data" defensive wrapper.** User-derived context lines are wrapped in
   `<untrusted_data>...</untrusted_data>` tags with a guardrail instructing the model to treat
   them strictly as data (`identity.js:108-109, 118-120, 147-157`) — a prompt-injection
   mitigation layered over a huge always-on context surface.

8. **Determinism / durability philosophy.** "All state in SQLite", zero in-memory cooldown
   Maps (only intentional ephemeral game sessions kept in-memory), a bounded 500-ID message
   dedup set to prevent double-processing, and `Promise.allSettled` so background tracking never
   blocks the reply (`bot.js:174-181, 215-232`; `CONTEXT.md §3`).

9. **Zero-test, cost-conscious design.** No test framework by deliberate decision
   (`CONTEXT.md §11.2`); cost controls everywhere: sleep mode, reaction-only 10%, per-concern
   rate buckets, deadpan token budget, hour cap, RAG only in full tier, and a visible
   `-(40/50)` budget suffix to the end user (`sharedPipeline.js:207-208`).
