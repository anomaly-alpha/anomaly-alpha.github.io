## 2. Dev process — "docs-driven, grill-gated, agentic, test-free"

### 2.1 Dated plan/spec/report directories
All work is authored as markdown first, in date-stamped, model-stamped directories:
- `docs/plans/YYYY-MM-DD/<model>/` (e.g. docs/plans/2026-08-02/deepseek-v4-flash/ with 6 plans: remediation, news-overhaul, nl-command-upgrade, reply-condenser, search-tavily-migration, tool-invocation)
- `docs/specs/YYYY-MM-DD/<model>/` (design specs with stable `[S1]`–`[S11]` section IDs; "do not renumber" rule, skarn-news-overhaul-design.md:163-164)
- `docs/reports/YYYY-MM-DD/<model>/` (audit findings)
- `docs/adr/` for Architecture Decision Records (`0001-tiered-context-assembly.md`)
- `docs/compose/plans/` and `docs/compose/specs/` (older nested pair, 2026-07-19→07-21, e.g. plan-A-foundation.md, plan-C-integration.md, new-skarn-identity.md)
- `docs/prompts/<model>/` for model prompts (docs/prompts/sonnet-5-medium/skarn-bot-doc-audit.md)

Two different models authored specs side-by-side: `deepseek-v4-flash` and `sonnet-5-medium` (e.g. docs/specs/2026-07-18/sonnet-5-medium/confidant-mode-v2.md vs the deepseek-v4-flash set on the same date).

### 2.2 The "grill" gate
Specs are explicitly written to be **grilled**: "meant to be grille-checked against skarn-bot docs before planning" (skarn-news-overhaul-design.md:5). Grill Q&A survives in the spec/plan commit history: `2d6a5fa` "NL command upgrade spec [S1]-[S11] + grill Q1-Q5"; `6ed11ea` "implementation plan for NL command upgrade + grill P1-P4"; `55b94cc` "grill news overhaul spec — drop search fallback...". Grill answers are locked decisions ("do not silently reverse them (re-grill first)", skarn-news-overhaul-design.md:140).

### 2.3 Plans are executable runbooks for AI agents
Plans open with `> **For agentic workers:** REQUIRED SUB-SKILL: Use compose:subagent (recommended) or compose:execute to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax` (docs/plans/2026-08-01/.../audit-fixes.md:3; docs/plans/2026-08-02/.../skarn-nl-command-upgrade.md:3). Tasks include exact file paths, exact diffs, `node -e` smoke scripts with expected output, and the exact commit message to use (`skarn-nl-command-upgrade.md:127-132`). This is a fully specified CI-less machine workflow — the repo is the deliverable.

### 2.4 Deliberately test-free, verified by smokes
No test framework exists by decision: "tests/ removed by decision (commit 8a736df), verified manually" (CONTEXT.md §11.2; pre-upgrade-audit.md:57). Verification instead is `node --check` + `SKARN_DB_PATH=$(mktemp -d)/... node -e` smokes + `node bot.js` boot, all documented in README.md:482-555 with expected outputs. Every plan carries a mandatory temp-DB guard: "a bare `node -e` would hit production `data/skarn.db`" (skarn-nl-command-upgrade.md:15).

## 3. Search & news systems

### 3.1 Search — Tavily-only, cache-first, fail-closed
`features/search/searchEngine.js`:
- `searchTavily()` POSTs to https://api.tavily.com/search with `search_depth: 'basic'` (1 credit) and `max_results: 5` (searchEngine.js:17-28). Missing key → `{ source: 'error', error: 'Tavily API key not configured' }` (line 15) — fails closed.
- `searchWeb()` wraps it with an LRU cache: 50 entries, 5-min TTL, LRU reorder on hit (searchEngine.js:4-6, 48-53).
- The provider chain shrank from Google CSE → DuckDuckGo → Wikipedia to Tavily-only because on Railway's shared datacenter IP all three legacy backends failed: "Google CSE returns null (free-tier quota exhausted), DDG flags the shared datacenter IP ('anomaly'), Wikipedia opensearch returns [],[],[] for compound queries" (skarn-news-overhaul-design.md:14). Migration: commit `f045069`, dependency `duck-duck-scrape` dropped (`8e12714`).
- Search serves two consumers: the `/search` command and the `search_web` AI tool (toolRunner.js:51-56).

### 3.2 News — 38-feed RSS/Atom pipeline, per-feed isolation
`features/news/newsFetcher.js`:
- **38 curated feeds across 5 categories** — tech 11, gaming 6, world 9, science 7, business 5 — URL-tested live 2026-08-02 (newsFetcher.js:16-60).
- Dual parsing: RSS `<item>` and Atom `<entry>` (newsFetcher.js:76-104) because Verge/CNET are Atom.
- **Per-feed isolation**: each feed fetched in parallel with its own try/catch + 8s timeout; "one dead/blocked feed costs only that feed" (newsFetcher.js:131-139; spec S8).
- **Published-time ordering**: `published_at` column (migration v2); reads `ORDER BY published_at DESC`; undated items fall back to `Date.now()` (newsFetcher.js:82, 191-196).
- **Retention/caps**: 200-article total cap, **per-category cap 40** so a chatty category can't starve the rest (newsFetcher.js:8-10, 168-171), 72h prune by `published_at` (line 184).
- **Dedupe**: exact URL wins, then normalized-title-60 (first 60 alphanumerics lowercased) for syndicated copies (newsFetcher.js:122-154).
- Scheduler cadence: fetch every 15 min + on boot (scheduler/index.js:60-63); evening digest posts at 18:00 UTC to per-guild `newsChannel` (newsDigest.js:5-28; scheduler/index.js:65-73).
- **Always-on news awareness**: `promptContext.js` injects `Happening now: [cat] headline | [cat] headline | ...` (newest per category, top 3, ~50 tokens/call) into every AI context — no longer intent-gated (spec skarn-nl-command-upgrade-design.md [S8]; implemented commit `9ff260a`).
- The `get_news` tool refreshes on demand if the cache is empty, with a `category` param (toolRunner.js:109-129; commit `75ec7f2`).

## 4. Reply condenser & model router

### 4.1 Reply condenser (`features/ai/condenser.js`)
A post-generation LLM pass that enforces a per-role **character** target (distinct from token budgets — "the former measures how a reply *reads*, the latter what it *costs*", skarn-reply-condenser-design.md:40). Behavior:
- **Zero-LLM short-circuit**: if `text.length <= target`, returns unchanged (condenser.js:25) — the hot path costs nothing for short replies.
- **Skipped content**: tool-call replies stay intact except `run_command` turns (condenser.js:26); code fences / markdown tables skipped via regex `/```|<\/?table|^\s*\|.*\|/m` (condenser.js:16).
- **Voice is load-bearing**: re-injects the exact role line + `ROLE_NATURE` so condensation stays in-character (condenser.js:29-40; spec [S11]).
- **Fail-open**: any error, too-short output (<16% of target), or output longer than the draft → returns the original (condenser.js:59-70).
- Model `gpt-4.1-mini`, max_tokens 140, temp 0.3 (condenser.js:11-13). Wired at sharedPipeline.js:167 — `condenseReply(reply, usedRunCommand ? 80 : target, ...)` so `run_command` turns get a hard ~80-char cap.
- Design spec: docs/specs/2026-08-02/.../skarn-reply-condenser-design.md; spec explicitly rejects a pre-reply "research" LLM call as highest-cost/lowest-margin (line 14, 27).

### 4.2 Model router (`features/intelligence/modelRouter.js`)
`selectModel(userMessage, hasKnowledgeMatch, complexityScore)` (modelRouter.js:3-14) upgrades to `AI_MODEL_COMPLEX` (default falls back to `AI_MODEL` = gpt-3.5-turbo) when ANY of:
1. the message matches a stored extracted entity with confidence ≥ 0.5 (`checkKnowledgeMatch`, modelRouter.js:16-27);
2. the message is >100 chars and contains `?` or `explain`;
3. preprocessing `complexityScore > 0.7` (tiebreaker, line 10).

### 4.3 Related intelligence layers (read but not asked to detail)
- `responseLearner.js` — classifies each reply as hit/miss/neutral by before/after sentiment delta (thresholds ±0.1) into `response_learning`, and produces per-user guidance strings (responseLearner.js:7-68).
- `toneAnalyzer.js` — few-shot LLM JSON tone analysis (`emotion/intensity/subtext/pacing`) with a keyword+sentiment fallback, 5-min cache (toneAnalyzer.js:26-106).
- `embeddings.js` — `text-embedding-3-small` + cosine similarity (embeddings.js:3-21).

## 5. The `run_command` tool — AI invoking any of 37 executable commands

This is the single most distinctive capability. Rather than ~70 per-command tool schemas (which would add 3,000–7,000 tokens of schema to every turn-1 call and degrade selection accuracy — skarn-nl-command-upgrade-design.md:38-42), Skarn exposes **one generic tool**:

1. **Dynamic enum**: `getTools()` builds the `run_command` enum at call time from `activationRegistry.getAll()`, filtered to `type:'command'` minus an exclusion list (`dice, coinflip, stats, weather, news, etch, remind, memory, search, lore` — the 9 dedicated-tool commands + AI-narrated lore) (toolDefinitions.js:12, 141-168). "A newly-activated command appears in the tool automatically — zero drift" (spec [S3]).
2. **Pseudo-message facade** (`features/tools/messageAdapter.js`): mention path wraps the *real* Discord message via `Object.create(source)` with rewritten `content`; consult path synthesizes a facade from the interaction. Both expose `author/guild/member/mentions/reply()` and a `capture()` that records the reply text (messageAdapter.js:38-76). `reply()` both sends the payload AND stores its text (embed title/desc/fields flattened) so the tool result carries the *real* output back to the model (messageAdapter.js:26-36).
3. **Permission gating**: `guildOnly` + `requiredPermissions` checked at the runner before dispatch, fail closed (toolRunner.js:200-213).
4. **Recursion guard**: dispatch goes through `handleActivation`, never `execute(interaction)` — "no nested AI from a tool". Single approved exception: poll's blank-options AI suggestion (toolRunner.js:227; spec [S5] grill P2).
5. **The "double-reply rule"** (spec [S7]): the command posts its own message, the tool result tells the model to reply with ≤1 short in-character line, and the condenser hard-caps the turn at ~80 chars (sharedPipeline.js:167).

The result: "Every command in the bot now has a natural-language path — nothing is slash-only anymore" (docs/NL-TOOLS.md:328-329). NL-TOOLS.md §11 is a complete 77-command reference with example phrasings, perm-level badges, and the three-way classification (runs-it / answers-in-character / points-to-slash).

## 6. Deploy / ops setup

- **pm2 ecosystem** (`ecosystem.config.js`): two supervised apps — `skarn-bot` (bot.js, max_restarts 10, restart_delay 5s, autorestart, timestamped logs) and `skarn-rpc` (rich-presence.js, max_restarts 5) (ecosystem.config.js:2-21). README.md:577-585 documents `pm2 start ecosystem.config.js`.
- **Crash restart loop**: `process.on('unhandledRejection'/'uncaughtException')` log AND `process.exit(1)` so pm2 restarts the bot (bot.js:21-28; commit "fix: exit on unhandled errors so pm2 restarts the bot").
- **SQLite backup** (`scripts/backup-db.js`, npm run backup): `VACUUM INTO` on a **readonly** connection — "reads the logical DB including -wal content, so no checkpoint is needed" (backup-db.js:15-18) — timestamped snapshots into `data/backups/`, 14-day retention prune (backup-db.js:22-27). Backups exist in the live tree (data/backups/skarn-20260802*.db).
- **Data hardening (2026-08-02)**: versioned migrations via `PRAGMA user_version` (db/migrations.js), `PRAGMA foreign_keys=ON` + WAL journal mode enabled, FK-safe prune paths (commit log 2026-08-02).
- **Env surface** (.env.example): DISCORD_TOKEN, CLIENT_ID, OPENAI_API_KEY, optional AI_MODEL/AI_MODEL_COMPLEX, SLEEP_START/END/TIMEZONE (default sleep 1–7 UTC), TAVILY_API_KEY. `.env` is gitignored and untracked (pre-upgrade-audit.md:64).
- **Runtime placement**: no Docker; a Railway deployment is implied by historical commit references (pre-upgrade-audit.md:6,14). Rich Presence is a *separate process* (discord-rpc, RPC_GUIDE.md).

## 7. Top-10 genuinely unusual traits (vs. a typical Discord bot)

1. **`run_command`: one AI tool invokes any of ~37 real commands through a fake Discord message.** The model executes actual server commands (level, poll, setwelcome, embed, lorebook, ticket...) with real permission checks, and the facade *captures* the command's reply so the AI relays true output. The command enum is rebuilt from the live activation registry on every call — new commands join the tool with zero code. (toolDefinitions.js:141-168; toolRunner.js:162-245; messageAdapter.js)

2. **A reply condenser that runs the LLM on the LLM.** After the main model replies, `condenseReply()` makes a *second* gated LLM call (gpt-4.1-mini) to squeeze over-target replies to a per-role character target — with a zero-call fast path, voice-preserving role injection, code-fence skip, and fail-open. (condenser.js; spec skarn-reply-condenser-design.md)

3. **A fully documented, grill-gated, agent-executable dev workflow.** Every feature is a dated spec with stable section IDs, must survive a documented Q&A "grill" against existing docs, then is planned as a checkbox runbook that literally tells an AI agent which files, diffs, smokes, and commit messages to use. (docs/specs, docs/plans; audit-fixes.md:3; skarn-nl-command-upgrade.md:3)

4. **Deliberately zero tests, replaced by reproducible `node -e` smokes.** The test framework was *deleted by decision*; verification is syntax checks + temp-DB `node -e` scripts with expected output embedded in README and every plan — a bold, documented anti-pattern. (CONTEXT.md §11.2; README.md:482-555)

5. **A 51-table SQLite schema under one file, with "all state in SQLite" as a hard rule.** Everything from channel moods and server-culture n-grams to cooldowns (moved from in-memory Maps in the 08-01 audit) is persisted; even ephemeral sentiment buffers and reaction timestamps live in SQLite. (db/skarn-schema.sql: 51 CREATE TABLE; CONTEXT.md §2)

6. **A 10,000-year-old demon Warmaster persona engineered like software.** 37 role lines, per-role token budgets AND per-role character targets, a reauthored "wisdom layer" (question-over-answer, absorb-before-responding, never name the philosophers), socratic-advice triggers with 18 phrasings, mood states (including `wrath`), and KV-cache-optimized prompt ordering. (persona/identity.js, persona/roles.js; CONTEXT.md §5)

7. **The AI is not just chat — it is the interaction layer.** Passive systems gate presence: probability-based attention gate, 10% react-only mode, sleep mode (default 1–7 UTC), deadpan banter chains, callback sampling, proactive check-ins, typing simulation with estimated delay, and a message-editor that "edits" replies for authenticity. (sharedPipeline.js; bot.js:68-118; CONTEXT.md §7)

8. **Railway-resilience engineering is a first-class concern.** Three search backends (Google CSE, DDG, Wikipedia) were replaced by Tavily when all failed from the shared datacenter IP; the news system rebuilt around per-feed isolation, 8s timeouts, and fail-open reads so "one blocked feed costs only that feed." (skarn-news-overhaul-design.md:14; newsFetcher.js:131-139)

9. **Multi-model, multi-day authored-in-repo engineering.** Specs were written by at least two different models (deepseek-v4-flash AND sonnet-5-medium on the same dates), plus a model-prompt archive (`docs/prompts/sonnet-5-medium/`), and the repo ships 86 markdown design/plan/report/ADR docs — a paper trail unusual for a bot.

10. **Production-grade ops for a hobby bot.** pm2 supervision of bot + separate Rich Presence process, crash-and-exit for auto-restart, `VACUUM INTO` WAL-aware DB snapshots with 14-day retention, versioned `user_version` migrations, FK enforcement, WAL mode, and 200-article/72h news caches — a lot of operational maturity relative to its 5-week lifetime.

**Honorable mentions:** always-on news awareness in every AI call (~50 tokens); Discord Rich Presence as a separate supervised process; a full persistent RPG ("Realm of Skarn", ~2,400 lines) with NPC memory, trading, and its own rate-limit buckets; and the auto-generated `/help` that derives themes live from `client.commands` with startup warnings for unmapped commands (helpPages.js:180-186).
