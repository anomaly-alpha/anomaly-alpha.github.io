About Anomaly Alpha

Where every number on this site comes from

by Anomaly · Updated November 7, 2026

Who runs this site

Anomaly Alpha is an independent, unofficial fan project for Invincible: Guarding the Globe, run by Anomaly. It is not affiliated with, endorsed by, or sponsored by Ubisoft, Skybound, or the game's developers. There is no editorial team behind it and no sponsored placements: it is one maintainer, a static site, and a set of checked-in data files.

The author profile is at Anomaly, and the source repository is on GitHub.

What this site is for

Most player questions about this game are arithmetic, not opinion: how many gems a week can I actually count on, and what does my league placement pay? This site exists to answer those with a number instead of a paragraph. It gives you a weekly gem calculator that adds up login, event, PvP, and code income for the modes you actually play, plus the reference tables that feed it: PvP payouts across all 14 leagues, event and login reward breakdowns, rank-up requirements, and a tracked list of active promo codes.

Where each number comes from

Every figure on the site is either transcribed from an official in-game or publisher screen, computed from those transcriptions, or explicitly labelled as an estimate. Nothing is invented to fill a table.

Promo codes

Each code is submitted at the official redemption portal, redeem.invincible.ubisoft.barcelona. If the portal accepts it, the code is listed as active and the reward it grants is recorded as shown on redemption. When the portal stops accepting a code, it moves to the expired list rather than being deleted, so the history stays readable.

PvP payouts

The Restricted Arena, Open Arena, and Multiverse War tables are transcribed from the in-game end-of-season reward screens, league by league and rank bracket by rank bracket. The calculator reads those transcriptions directly, so a payout shown in the tool and a payout shown in the PvP guide cannot disagree.

Login and event rewards

Login income is summed from the daily, weekly, and monthly reward tracks. Event income reflects the per-cycle maximums for The Long Haul and Earth's Defenders. Because event rotations change, the site gives the reward ceiling and tells you to confirm live dates in-game rather than publishing a schedule it cannot keep accurate.

Rank-up requirements

The rank-up progression table is adapted from the Ubisoft help center, cited at the bottom of the table itself. Per-rarity XP figures are community estimates and are labelled as estimates wherever they appear, with a pointer to a dedicated community calculator for exact current-to-target totals.

Weekly totals

The headline weekly total is not a hard-coded claim: it is the sum of whichever modes you have selected, using the tables above, recalculated in your browser as you change leagues, ranks, and reward modes.

How the site is built

The site is plain static HTML generated ahead of time. It has no backend, no database, and no account system, and it never asks for your player ID, credentials, or anything else tied to your game account.

The numeric tables, totals, and code lists are produced by build scripts that read checked-in data files, so those numbers are always derived from the same source rather than retyped by hand into each page. That is why the calculator, the guides, and the FAQ agree with each other. The explanatory text around those tables is written and edited by hand.

All calculations run locally in your browser. See the privacy policy for what analytics are collected.

What this site does not claim

  • It is not official, and it does not speak for the developer or publisher.
  • It does not publish a live event schedule, because rotations shift and a stale calendar is worse than none.
  • XP-per-rarity figures are estimates, not datamined values.
  • Code availability can change at any time. A code listed as active was confirmed against the portal when it was last checked, not guaranteed to work when you read it.

Corrections

If a number here is wrong, the fastest route is an issue on GitHub. Corrections are made in the underlying data file and the pages are rebuilt from it, so a fix propagates everywhere the figure appears instead of being patched on one page.
